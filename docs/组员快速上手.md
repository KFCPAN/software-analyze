# 组员快速上手（Docker 一键全栈）

> 适用：只想登录系统做联调/写报告截图，**不想装 JDK/Maven/Python** 的组员。
> 每个人在自己电脑上跑一套完整系统，互不依赖组长的机器，数据互不影响。
> 维护者全栈指南（含 IDEA/匹配引擎调试）见 [启动指南.md](启动指南.md)。

## 装什么（只需两个）

| 软件 | 验证命令 |
|---|---|
| Docker Desktop | 右下角鲸鱼图标在跑 |
| Node.js + pnpm | `node -v` / `pnpm -v` |

## 三步跑起来

```powershell
# 1. 克隆仓库，在仓库根目录起数据库+后端（首次要拉镜像和构建，约 5~15 分钟，耐心等）
docker compose -f deploy/docker-compose.yml --profile app up -d --build

# 2. 起前端（第一次要装依赖）
cd web
pnpm install
pnpm dev

# 3. 浏览器打开 http://localhost:5173 ，用演示账号登录
```

## 演示账号

- 普通用户：`demo01` ~ `demo10`，密码统一 `Demo123456`（**D 大写**，区分大小写）
- 登录后随便发布失物/招领、认领、走审核核销流程，都是你自己的库，不影响别人

## 验证后端起来了

浏览器访问 http://localhost:8080/api/categories ，返回 JSON 分类列表就说明后端正常。

## 常见问题

1. **拉镜像超时/失败** → 校园网直连 Docker Hub 不通。二选一：
   - 把 `deploy/docker-compose.yml` 里 `image: pgvector/pgvector:pg16` 改成 `docker.m.daocloud.io/pgvector/pgvector:pg16`，并取消 backend 服务里 `build.args` 的注释；
   - 或在 Docker Desktop → Settings → Docker Engine 的 `daemon.json` 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]` 后重启 Docker。
2. **登录提示"网络连接失败"** → 八成是后端容器没起来。`docker logs lnf-server` 看日志；或浏览器直接访问上面 8080 的验证地址确认。
3. **8080/5432 端口被占** → 本机已有别的服务占端口。改 `deploy/docker-compose.yml` 的端口映射（如 `"8081:8080"`），同时把 `web/.env` 的 `VITE_API_BASE_URL` 改成对应端口。
4. **想重置环境重来** → `docker compose -f deploy/docker-compose.yml --profile app down -v`（`-v` 删除数据卷），再重新 `up`。
5. **不需要演示数据以外的残留** → 新装的系统只有演示账号（demo01~demo10）和空表，物品自己发；想要和开发组一致的 205 条演示物品，在仓库根目录跑 `python scripts/import_dataset.py`（需 Python3 + matcher 已启动，见启动指南第②节）。

## 说明

- 智能匹配引擎（matcher）不在一键全栈里（模型权重大），登录/发布/认领/核销等核心功能不需要它；
- 管理员后台（`admin`）的密码是占位哈希，暂无有效密码，后台相关功能演示找组长。
