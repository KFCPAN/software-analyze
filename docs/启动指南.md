# 项目启动指南（全栈）

> 更新：2026-10-19 · 维护：HWM
> 启动顺序：**① 数据库 → ② 匹配引擎 → ③ 后端 → ④ 前端**，前一个不起来后面别动。

## ⓪ 新成员三分钟全栈（Docker 一键，推荐）

**不需要 JDK、Maven、Python**，只要 Docker Desktop + Node/pnpm。组员各自跑一套完整系统，互不影响（CORS 已放行 localhost:5173，前端零配置）。

```powershell
# 1. 克隆仓库后，在仓库根目录执行：数据库 + 后端一起起（首次自动建表、写演示账号）
docker compose -f deploy/docker-compose.yml --profile app up -d --build

# 2. 起前端
cd web
pnpm install
pnpm dev

# 3. 浏览器打开 http://localhost:5173，用 demo01 ~ demo10 登录（密码 Demo123456）
```

- 后端接口验证：http://localhost:8080/api/categories 返回 JSON 分类列表
- 想要和开发库一致的 205 条演示物品（含照片）：在仓库根目录跑 `python scripts/import_dataset.py`（脚本走真实 API 自动登录导入，需要 Python3 + openpyxl + requests，且 matcher(:9000) 已启动；仅登录联调可跳过）
- 想重置整套环境重来：`docker compose -f deploy/docker-compose.yml --profile app down -v`（`-v` 会删掉数据卷）
- 后端容器日志：`docker logs -f lnf-server`

**国内网络拉镜像超时的处理**（二选一）：
1. 临时：把 `deploy/docker-compose.yml` 里 `image: pgvector/pgvector:pg16` 改为 `docker.m.daocloud.io/pgvector/pgvector:pg16`，并取消 backend 服务 `build.args` 两段注释；
2. 一劳永逸：Docker Desktop → Settings → Docker Engine，在 `daemon.json` 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]` 后重启 Docker。

> 说明：智能匹配引擎（matcher，FastAPI + BGE/CLIP，模型权重大）不在 compose 里，需要匹配功能时按第②节在本机启动；没有它登录、发布、认领等核心功能不受影响。组长本人日常开发仍按第①~④节（IDEA 跑后端），`docker compose up` 不加 `--profile app` 时行为和以前完全一致（只起数据库）。

## ① 数据库（PostgreSQL 16 + pgvector，Docker）

```powershell
docker start lnf-postgres
```

验证：`docker ps` 看到 `lnf-postgres ... (healthy)` 即可。
首次运行或容器被删才需要重建（参考 db/ 目录说明），平时一条 `docker start` 就够。

## ② 智能匹配引擎（FastAPI，端口 9000）

```powershell
cd matcher
.venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 9000
```

验证：浏览器打开 http://localhost:9000/docs 能看到接口文档页。
注意：首次启动要加载两个模型（BGE + CLIP），等 10-20 秒属正常。

## ③ 后端（Spring Boot，端口 8080）

**⚠️ 不要用 `mvn spring-boot:run`** —— 项目路径含中文（"软件实践"），Maven 给子进程传 classpath 时编码错乱，必现 `ClassNotFoundException: com.lnf.server.ServerApplication`。已实测 fork=false、UTF-8 JVM 参数均无效，放弃此方式。以下两种方式任选：

### 方式 A：IDEA（推荐，日常开发）

1. IDEA 打开 `server/` 模块
2. 确认 Project SDK 选 **17**（不是 25）
3. 找到 `ServerApplication.java`，点方法旁的 ▶ 绿三角

### 方式 B：打 jar 运行（演示/联调用）

```powershell
cd server
# 打包（如果代码没改可跳过，target 里有现成的）
D:\apache-maven-3.9.11\bin\mvn package -DskipTests
# 启动（注意用 JDK 17 的 java，不要用系统默认的 25）
D:\jdk-17\bin\java -jar target\lnf-server-0.0.1-SNAPSHOT.jar
```

验证：浏览器访问 http://localhost:8080/api/categories 返回 JSON 分类列表。
注意：如果打包报 "Unable to rename ... .jar"，说明旧服务还在跑占用着 jar，先在任务管理器结束 java 进程（或 `Stop-Process` 占用 8080 端口的进程）再打包。

## ④ 前端（Vue 3 + Vite，端口 5173）

## 端口速查

| 服务 | 端口 | 启动方式 |
|---|---|---|
| PostgreSQL | 5432 | `docker start lnf-postgres` |
| 匹配引擎 | 9000 | uvicorn（matcher/.venv） |

## 常见问题

1. **后端启动报数据库连接失败** → 第①步没做，`docker start lnf-postgres`
2. **发布信息后没有匹配结果** → 第②步匹配引擎没起，后端调 9000 端口失败
3. **前端调接口 401** → 先登录拿 token；前端会自动带，没自动带就检查 `.env.development`
4. **`mvn spring-boot:run` 报 ClassNotFoundException** → 中文路径问题，用方式 A 或 B，别用这条命令
5. **打包 jar 失败 "Unable to rename"** → 旧 jar 正在被运行中的 java 进程占用，先停服务再打包
6. **接口正常但图片加载不了（返回 500 JSON）** → 历史问题：`upload-dir` 曾是相对路径，后端不在 `server/` 目录启动就会找不到图片。已改为绝对路径配置（application.yml），现在从任何目录启动都不影响。前端另注意：`<img>` 的 src 要拼后端 baseURL，不能只写 `/files/...` 相对路径（ItemCard 等组件已处理）
7. **前端突然连不上后端 / 登录不了** → 校园网是 DHCP 动态分配，后端机器的 IP 会变（重连、换楼宇都会变，如 10.70.164.4 → 10.70.138.4）。前端在自己机器上改 `web/.env.development` 的 `VITE_API_BASE_URL` 为新 IP 即可（该文件不入库，参考 `web/.env.development.example` 模板）。后端查当前 IP：`ipconfig` 找 WLAN 下的 IPv4
